# 审查与验证

这是面向本地诊断和代码审查的 `0.1.0-preview` 预发布版，目前仅经过单机验证。

## 要审查什么

1. `Get-ComponentInfo` / `Select-Component`：按实际进程路径选择组件；旧修复缓存不能代替未知的当前运行组件；无法检查进程时不虚报活跃状态。
2. `New-VerifiedImage`：只接受两个完整文件 SHA-256；准确检查 42 字节谓词区域；构造修改后的完整镜像并核对预期完整 SHA-256。
3. `Invoke-FileChange`：原版签名为 Valid；先生成/校验使用者自己的完整备份；独占文件、只写对应区域、刷新磁盘并验证完整读回；故障时回滚。
4. `Invoke-Recovery`：修改前要求明确接受签名变化或恢复行为；Codex 和原生组件必须退出；未知文件、清单不完整、备份不合格时拒绝写入。
5. `Write-LocalReport`：只记录组件元数据；遮蔽用户配置目录前缀；不收集网页或对话，不发送网络反馈。
6. `build.ps1`：明文允许清单；ZIP 内不能有 `.exe`、备份、报告、测试临时文件、个人路径或聊天 ID。

## 已有验证与边界

- 原生行为依据：同一台中文 Windows 电脑上，原组件在默认独立 Chrome 配置中读取失败；只修改该谓词后，原生 Chrome/日常 Edge 的读取、输入回读、点击和导航成功，另验证了 Chrome 键盘输入与回车导航。
- 这些原生测试发生于本次组件修复阶段，不能当作本工具每次检测都自动完成了功能验收。
- 本交付包的 PowerShell 写入实现另经真实签名原文件的未执行副本测试；没有为打包而撤掉已安装的修复。
- 没有记录本机失败瞬间内部 UIA getter 值，也没有做运行时恢复/重新应用的完整 A/B 实验；网上韩文报告提供了更直接的运行时证据。
- 只验证当前完整文件对；没有声称所有 `0.7.13` 文件、其他版本、所有语言、所有相同报错都适用。
- 尚未验证完整应用/系统重启后的持续性、未来更新、多设备兼容性。新版本可能已经修好，不应强制套用旧补丁。
- 设计目标为 Windows x64 + Windows PowerShell 5.1 / PowerShell 7；实际测试环境及测试结果见 `validation.json`。

## 发布前

使用方应先在自己的可恢复环境中检查文件与实际原生操作。正式发布者可在 Windows 10/11、多种 UI 语言上增加独立验证；任何新增支持文件必须有完整哈希、准确指令映射和原生实测证据。这个预览版本没有通配补丁或“强制应用”开关。
